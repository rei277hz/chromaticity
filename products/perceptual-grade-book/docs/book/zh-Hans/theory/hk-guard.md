# 有界 H–K 保护

创作性的明度与彩度请求可能落到 \(H^2<66C\)，那里无法恢复实数非彩色明度。保护把该修复分摊为一个有界的 \(H\) 抬升和一次 \(C\) 缩减，同时保持色相不变。

## 设定能量拐点

把阶段 2 的点逐像素保留为参考。定义请求的明度平方 \(X\)、请求的非彩色能量 \(D\) 与参考能量 \(E_0\)：

$$
X=H^2,\qquad D=X-66C,\qquad E_0=\max(H_2^2-66C_2,0),
\qquad\delta=\frac{E_0X}{E_0+X}.
$$

调和式用 min/max 归一化求值，以避免大乘积。两个能量都为零时 \(\delta\) 为零。其系数是固定的内部常数 1.0，与图像统计无关。

当 \(D\ge\delta\) 时保留请求。低于拐点时使用正的能量下限：

$$
t=\frac{\delta-D}{\delta},\qquad
E=\frac{\delta}{(1+4t+10t^2)^{1/4}}.
$$

该 \(E\) 分支在 \(D=\delta\) 处与前者值、斜率与二阶导数均衔接。实现使用 \(v=1/(1+t)\) 以获得有界的中间量。零 \(\delta\) 分支取相应的非负能量极限。

![保护能量与实域边界](../assets/figures/guard-energy.png)

<p class="figure-caption">拐点过渡到正非彩色能量。修复后的点仍满足 \(H^2=66C\) 之上，因此逆有实数 \(J_A\)。</p>

## 分摊修复

令 \(Z\) 为能量缺口，\(L\) 为明度平方的最大抬升。把平滑有界的一部分 \(G\) 分配给 \(H\)：

$$
Z=\max(E-D,0),\qquad L=(1.2^2-1)X=0.44X,
\qquad G=\frac{LZ}{\sqrt{4L^2+Z^2}}.
$$

然后恢复输出对：

$$
H_{\mathrm{out}}=\sqrt{X+G},\qquad
C_{\mathrm{out}}=\frac{X+G-E}{66},\qquad
\mathbf u_{\mathrm{out}}=\frac{C_{\mathrm{out}}}{C}\mathbf u.
$$

黑与 \(C=0\) 使用显式零分支。舍入保护把 \(C_{\mathrm{out}}\) 约束在零与请求的 \(C\) 之间。合格输出满足 \(H\le H_{\mathrm{out}}\le1.2H\) 与 \(0\le C_{\mathrm{out}}\le C\)。在请求 \(H=50,\ C=80\)、参考 \(H=50,\ C=20\) 时，输出约为 \(H=58.188,\ C=48.142\)。

![在 H 与 C 之间分摊修复](../assets/figures/guard-boundary.png)

<p class="figure-caption">在请求的 \(H=50\) 处，更强的彩度请求逐渐使用有界抬升与更多彩度缩减。抬升逼近固定的 20% 相对上限。</p>

## 把能量带入解码

解码器直接接收 \(E\)。若由四舍五入的 \(H_{\mathrm{out}}^2-66C_{\mathrm{out}}\) 重建，会抹掉很小的正非彩色分量。DCTL、解析 Python 模型与原生节点都保留这条能量路径。精确复位、中性色与未改变的请求保留其旁路行为。负的请求 \(H\)、非有限值与锥响应极点遵循必要的逆域策略。

该保护处理模型的实能量边界。输出色域与影调渲染仍在后续。LUT 采样的是完整受保护的变换；插值 RGB 有其自身的有限网格误差。[样例对比](#重建样例对比)分别说明这两个问题。

实现来源是 `libraries/perceptual-grade-reference/src/responses.py` 中的带符号 H–K 映射与能量传递、`libraries/perceptual-grade-core/src/perceptual_grade_core/model/hk_guard.py` 中的保护本身，以及位于 `products/perceptual-grade-blender/src/graph/` 与 `products/perceptual-grade-dctl/src/core.dctlh` 的产品图。测试覆盖独立高精度计算、float DCTL 一致性、原生表达式、带符号输入以及采样的 EXR/PQ 样例，均通过 [Buck2](../development/building.md) 运行。

## 投影到导出立方体

H–K 修复留下的是一个有效的外观对，而不是可显示的 RGB。参考实现在导出处施加第二个、独立的保护，两者不可混为一谈：

1. H–K 修复使用 Tone 之后的参考能量，得到 \((H_g,a_g,b_g)\) 并携带 \(E\)。
2. 解码器在该对上运行。任何锥响应逼近 \(\lvert r\rvert=400\) 极点的点会被拒绝，而不是被截断。
3. 立方体保护在修复后的 \(J_A\) 与色相处搜索能解码进原生 AP1 立方体的最大彩度。它先在锥坐标中由八个立方体顶点框定半径，用该明度与色相处的拟合容量作为搜索种子，随后二分，并用实际解码器验证每一次试探。容量种子只是起始猜测，从不决定结果。只有当 RGB 有限且位于 \([0,1024]^3\) 内时才保存。

因此立方体保护在固定 \(J_A\) 与色相的同时缩减彩度，这是与 H–K 保护的有界明度抬升不同的策略。它是投影而非逆：两个不同的外观请求可以导出到同一 RGB，投影按构造是有损的。只有 H–K 保护参与上面的定参考可逆性论证；立方体保护的输出不继承该性质。

调色中间量在导出之前从不被迫经过立方体保护。调色在原始带符号外观坐标上进行，保护只在边界运行，因此一个 Stack 可以让同一个外观值穿过若干阶段，并在最后投影一次。仅导出时修复也意味着逆向不能假定前向路径已经投影过。

早期 1.23.2 版本在其自身的立方体域上施加等价的导出保护。跨版本比较必须说明上界：本部分描述参考实现的 \([0,1024]\) AP1 域，而 1.23.2 的采样网格记录在归档的 LUT 研究中。

## 历史评估

本节记录的是较早的保留 C 保护及其最初的 LUT 编码。当前实现使用[有界共享保护](hk-guard.md)与[线性 RGB 插值的非对称输入网格](lut.md)。下面的测量记录的是那次较早的实验。当前的回归样例与验收结果在[验证](../development/building.md)中说明。包中保留了采样的 EXR 探针与 PQ PNG。当前 Buck2 构建用这些样例生成下面的对比。

### 记录实验：1.4.0

选定系数为 \(k=1.0\)，在两个实现中都是固定值。Color 阶段保护保留请求的彩度与色相，并在实域边界附近平滑抬升 H–K 明度。DCTL 与扩展的原生节点计算高度一致。即使在强调色下，\(65^3\) LUT 仍是显著近似，即使有这一更平滑的保护。

### 计算

使用实际的 modCAM16 彩度 \(C=\sqrt{a^2+b^2}\) 与 \(H=J_{\mathrm{HK}}\)，其中 \(H^2=J_A^2+66C\)。默认参考／适应亮度保持 203/20.3 nit。\(H=100\) 标识参考白中性色；HDR 的 \(H\) 继续高于 100。

把 Tone 阶段输出 \((H_2,a_2,b_2)\) 作为 Color 阶段请求 \((H,a,b)\) 的参考。定义：

$$
E_0=\max(H_2^2-66C_2,0),\quad D=H^2-66C,\qquad
\delta=k\frac{E_0H^2}{E_0+H^2}.
$$

$$
E=\begin{cases}
D,&D\ge\delta,\\[2pt]
\displaystyle\frac{\delta}{1+t+t^2},\quad t=\frac{\delta-D}{\delta},&D<\delta.
\end{cases}
\qquad H_{\rm safe}=\sqrt{66C+E}.
$$

逆接收 \(J_A=\sqrt E\) 与原始 \((a,b)\)。当 \(\delta\) 为正时，两个分支在值与斜率上衔接。平滑拐点从有效域内部开始，提供向边界的渐变。当 \(\delta=0\) 时，极限为 \(E=\max(D,0)\)。

复位时 \(D=E_0\)，且对 \(0<k\le1\) 有 \(\delta\le E_0\)，因此请求被精确保留。对中性色 \(D=H^2\ge\delta\)。\(\delta\) 的调和式避免了两个明度平方值相乘。有理分支使用有界变量 \(v=1/(1+t)\)，求值 \(E=\delta v^2/(1-v+v^2)\)。

精度很重要：解码器直接携带 \(E\)。由四舍五入的 \(H_{\mathrm{safe}}^2-66C\) 重建，可能在 float32 中丢掉整个很小的非彩色分量。这条直接能量路径由解析 DCTL、Python 烘焙／示波器与原生节点共享。带符号 RGB 对主信号与其中性锥偏移使用成对的参考。

系数是一个全局工程选择。\(\delta\) 与该点的坐标确定性地变化，和所有其他颜色变换项一样。图像统计、相邻像素、曝光元数据与示波器选择都不影响 \(k\)。生产 UI 与保存的调色参数中不包含系数控件。

例如，取输入点 \(H_2=50,\ C_2=20\) 并请求 \(H=50\)：

| 请求 \(C\) | 先前输出 \(C\) | 新输出 \(C\) | 新输出 \(H\) |
|------------:|------------------:|-------------:|-------------:|
|          20 |             20.00 |           20 |        50.00 |
|          30 |             30.00 |           30 |        50.24 |
|          40 |             37.88 |           40 |        53.53 |
|          80 |             37.88 |           80 |        72.88 |
|         160 |             37.88 |          160 |       102.79 |

保护使这些高彩度请求保持可区分。负的请求 \(H\)、非有限值与逆锥响应的有限域保留其既有的成对回退。输出色调与色域映射仍在后续。

### 照片与流程

提供的四张半浮点 EXR 标识 Rec.2020/D65 色度。数值按线性 RGB 解释，参考白 1.0 = 203 中性 nit。带符号通道被保留。

| 来源     |  尺寸 | RGB 最小／最大 | 负通道比例 |
|----------|------------:|----------------------:|------------------:|
| IMG_0436 | 4032 × 3024 |    −0.01275 / 1.02344 |            0.929% |
| IMG_0441 | 4032 × 3024 |    −0.00450 / 1.00488 |            0.605% |
| IMG_0446 | 4032 × 3024 |    −0.00243 / 0.87695 |            0.658% |
| IMG_0472 | 3024 × 4032 |    −1.75488 / 4.92578 |            2.258% |

样例每十二行与每十二列各保留一个采样，并尊重每张 EXR 的数据窗口。原图哈希与采样方法记录在 `tests/blender/fixtures/hk-real-world/metadata.json`。每个候选接收相同的输入像素与滑杆设置。

Practical 调色把 Global C Gain 设为 +0.35 档、Midtones Cₗ → J 设为 −4、White Cₕ → J 设为 +6，并加入小幅 Adaptance 与 Hue 改动。Chroma ×8 使用 Global C Gain +3 档。Darken + chroma 把 Midtones \(a\) → J 设为 −15、White b → J 设为 −20，并配 Global C Gain +2 档。

Tonal chroma 把 Midtones Cₗ → C 设为 +2、White Cₕ → C 设为 +3，加入带符号 a/b 贡献与 Global C Gain +0.5。Strong Adaptance 使用 \(a=[30,-50,60,-80]\)、\(b=[-30,50,60,80]\) 与强度 0.75。Remap + color 把输入 Midtones、White 与 Highlights 放到 50、350 与 1500 nit，加入 +1.5 档全局彩度增益并施加色调 J/C 改动。

最大控件压力调色把四个 Cₕ → C 值全设为 +16 档，Global C Gain 设为 +3，请求高达输入彩度的 524,288 倍。其他设置保持默认。

JSON 报告包含每个参数，包括上面缩写的设置。广泛扫描每个候选使用 254,016 像素：四张照片每隔 24 像素采样，取 0/+2/+4 档曝光，在 ACEScg 与 Linear Rec.2020 中。它比较了先前的上限与 \(k\)=0.05/0.1/0.2/0.4/0.75/1.0：共 98 组调色／空间／系数对比。该数值扫描中的 ACEScg 转换显式使用 XYZ 与 CAT16 D65→ACES 适应。

显示研究另行使用 Blender 自带的 OCIO 输入转换与 ACES 2.0 HDR 1000 nit 视图，输出为 Rec.2100-PQ。每个候选使用 75,264 像素，取 0/+2 档，\(k\in\{0.1,0.4,0.75,1.0\}\) 加上旧上限。显示误差是所得显示 RGB 之间的 \(\Delta E_{\mathrm{ITP}}\)。这些曝光包围把提供的 HDR 照片推进到约 1000/4000 nit 的预期范围；峰值 RGB 通道值不是亮度测量。

### 系数选择与插值误差

\(65^3\) 立方体保留其带符号 asinh 输入／输出整形、±64 输入分量域、四面体插值与外侧单元外推。每个 LUT 与其自身的解析模型比较，因此该表把插值精度与新旧保护之间预期的外观变化区分开来。

把每像素的相对 RGB 误差定义为 \(\frac{\lVert\mathbf{RGB}_{\mathrm{LUT}}-\mathbf{RGB}_{\mathrm{analytic}}\rVert_\infty}{\max(0.01,\lVert\mathbf{RGB}_{\mathrm{analytic}}\rVert_\infty)}\)。P99 是 99% 采样像素落于其下的误差。\(\Delta E_{\mathrm{ITP}}\) 是显示空间距离，不是百分比。

| 调色             | 旧 RGB 误差 P99 | \(k=1\) RGB 误差 P99 | 旧 \(\Delta E_{\mathrm{ITP}}\) P99 | \(k=1\) \(\Delta E_{\mathrm{ITP}}\) P99 |
|------------------|------------------:|------------------:|---------------:|---------------:|
| Practical        |             8.21% |         7.69% |           9.74 |       6.84 |
| Chroma ×8        |            85.93% |        77.96% |      89.06 |         102.06 |
| Darken + chroma  |            96.25% |        54.82% |          86.39 |      80.59 |
| Tonal chroma     |            89.57% |        60.99% |         112.87 |      88.65 |
| Strong adaptance |            69.76% |        38.71% |          45.98 |      44.76 |
| Remap + color    |            74.65% |        53.43% |          63.08 |      47.42 |

系数 1.0 在六组显示研究调色中的相对 RGB P99 全部最低，在五组中显示 P99 最低。Chroma ×8 的显示结果更偏向更小的拐点与先前的上限。六组调色中，其显示 P99 的等权平均为：旧上限 67.85，\(k=0.1\) 为 67.09，\(k=0.4\) 为 63.00，\(k=0.75\) 为 61.89，\(k=1.0\) 为 61.72。这支持把 1.0 作为经过测试的折衷，连同其精确复位保证，而不是普遍感知最优。

强调色下 LUT 差异仍然可见。更平滑的 H–K 保护在多数测试情形中改善插值，而逆外观变换、带符号扩展与整形后的 RGB 坐标在单个立方体单元内仍可能快速变化。单一系数无法为该近似给出整体精度界。

+4 档压力包围还会把某些输入分量推离 ±64；边缘外推在那里可能产生极大误差。这些最大值在各图像／曝光的 JSON 中单独报告。最大控件调色在每个工作空间中触发其余逆响应域保护达 254,016 像素中的 236,390 个；混合有效与回退顶点会使 LUT 结果很差。六组代表性调色在广泛扫描中解析逆回退为零。这些是与 H–K 实域修复不同的独立限制。
