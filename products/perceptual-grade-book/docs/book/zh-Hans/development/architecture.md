# 架构与运行时

## 跨编辑器共享参数所有权

`graph/grades.py` 使用只保存参数的 NodeTree ID `PGGradeData`。节点以 `pg_grade` 指针引用该 ID。节点 PropertyGroup 保存空选择框和手柄拖动所需的本地编辑状态；选择 Grade 后，读取以该 Grade 为准。Grade 保存模型参数和源白点跟随状态；渲染方式、输入连接及界面焦点保持本地。共享编辑先同步各用户，再通过各节点已有的求值器和烘焙调度更新资源。

`PGShaderGrade` 和 `PGCompositorGrade` 的绘制回调显示原生 `template_ID` 选择框。新建操作创建默认 Grade，或复制所选数据块及当前动作；取消关联只清除本节点的引用。属性回调、指针更改和批量拖动使用受保护的更新过程，避免递归。取消首次拖动会删除该次创建且已无用户的 Grade。

常规保存和禁用扩展时，界面节点转换为原生节点组，保留插槽标识及默认值、连线、名称、布局、设置和 Grade 指针。保存完成（包括失败）、加载和重新启用后恢复界面表示。在这些生命周期边界之后，调用方需要重新取得节点 RNA 对象。Blender 5.2 将扩展 RNA 与普通自定义属性分开保存，因此转换必须显式复制 RNA。保存的原生图无需注册自定义节点类即可求值；恢复或自动保存快照仍可能需要扩展。

扩展只管理具有完整当前格式标记的节点，其他节点组保持原样。链接数据保持只读；新建本地副本后才能编辑。共享参数关键帧写入 Grade ID。共享参数不会合并着色器和合成求值图。

每个使用者节点以一个结果恒为零的驱动器声明对 Grade ID 的依赖，让 Blender 自己的依赖图求值共享参数动画。可移植的原生表示会静音该依赖。替换节点时，在删除旧节点之前迁移所属节点树的动画路径，以保留插槽关键帧和依赖驱动器。Blender 5.2 中，求值节点组的赋值推迟到自定义节点的初始化或复制回调结束后；在回调内赋值可能导致 ID 用户计数错误。

## 反向与节点独立堆栈

`model/inverse.py` 提供无 SciPy 依赖的半解析反向求值和完整正向残差检查。`model/transforms.py` 按顺序计算不可变调色快照。`graph/stacks.py` 保存节点独立的调色引用／方向列表，复制节点时独立复制列表但保留共享调色引用。未用于图像计算的 SUM 驱动器声明各调色的动画依赖。

普通 Grade 节点始终正向应用，渲染方式仅在侧栏选择。启用状态和方向属于堆栈条目；全部矩阵与非线性步骤烘焙为单个 LUT，旁路和空条目跳过。CPU 工作线程只处理 NumPy 数据，GPU 计算和 Blender 数据发布在主线程。编辑时先安装 33³ 预览，稳定后细化为 65³。连续拖动期间，运行中的预览可完成，新修改合并为一个后续请求；过期的最终结果不能发布。输出与示波器使用同一已安装 LUT，首次预览前直通输入并显示状态。最终渲染与正常保存要求最新 65³。正常保存与禁用时显式保存列表和原生求值图。不会转换旧版项目。

包含反向条目的烘焙分为 33³ 预览和其余顶点的细化两个阶段，各阶段使用一个待解池，收敛顶点逐步退出。所有共享顶点逐位复用，不再次求解。带阻尼的 Broyden 更新复用雅可比矩阵；带括区间保护的 Newton 法求解 Tone 和固定参考能量的 H–K 防护。解析正向求值共享曲线与防护计算，并简化有符号提升所需的中性偏移。取消标记在数值检查点中止过时任务。扩展只增加 Python 源代码，使用 Blender 自带 NumPy。

## GPU 上下文、调度与恢复

`model/gpu.py` 提供已安装的解析 float32 求值器和渐进烘焙器，
`model/gpu_shader.py` 保存运行时着色器源。`graph/gpu.py` 按窗口上下文缓存程序，
用独立 float64 参考进行启动检查，并为节点、视口和图像编辑器注册绘图回调。
`graph/lut.py` 在回调中进行数值计算，由定时器发布 RNA／图像；GPU 对象不进入 CPU 线程池。

后台在主线程显式调用 `gpu.init()`，不更改渲染引擎。前台需要可用绘图区域；
关闭该区域／窗口、着色器异常和无物理图形设备会转用 CPU。仅矩阵变换和奇异反向矩阵
也使用 CPU。侧栏报告实际选择，不增加新的渲染方式。

参数纹理使用稳定容量，每个快照上传一次，完成或取消时释放。输入／输出纹理在启动小探针、
部分批次和后续编辑中均保持固定 1024×128 布局，输出纹理由缓存程序持有，避免重复布局专门化。自适应批次以温态数值工作
约 20 ms 为目标；首次着色器／驱动编译为同步操作，可能远超此目标。每批包含上传、
完整 Grade 序列、回读、设备审计、AP1 转换和 float32 存储。标记顶点在每个预览／细化
阶段末尾汇总为一个共享 CPU 修复池，修复完成后才可发布。
GPU 各顶点独立运行有界求解，不是 CPU 的逐步缩小批量待解池。

撤销／加载清理数值任务但保留程序；完整注销移除回调并释放程序。保存／渲染复用当前
完成表；前台生命周期回调没有保证的绘图上下文，因此待完成工作改用 CPU。
若已发布匹配预览，CPU 细化保留所有公共顶点。float32 策略与诊断见
[数学规范](forward-inverse-math.md#已安装的-gpu-求值剖面)。

## 白点与场景坐标

阶段 1 使用双精度 XYZ 矩阵及其记录白点作为权威数据，线性控制只提供推导编辑视图。Grade 工作白点固定默认为 D65。场景边界通过 Blender 原生颜色转换连接固定内部 RGB 基底，白点之间使用 Bradford。普通节点将阶段 1 放在非线性 LUT 外；堆栈把全部阶段和白点衔接烘焙到一个 LUT。切换场景空间仅更新边界矩阵。动画矩阵保留其记录白点，每帧进行所需共轭变换，无需重写关键帧曲线。

## 显式编辑与示波器

调色节点与堆栈铅笔根据当前编辑器唯一的图表目标及可见状态推导高亮，不保存独立的节点激活标记。点击另一个铅笔会激活其节点并替换编辑目标；关闭图表取消高亮。保留但未显示的堆栈目标再次点击铅笔时会重新打开。

`graph/editing.py` 为每个编辑器保存临时编辑目标。稳定条目键跟踪列表中的具体位置，即使同一 Grade 被多次引用；不创建辅助节点或复制 Grade 参数。铅笔激活条目并打开图表，旁路、移除、清空或只读条目不可编辑。侧栏和手柄写入共享 Grade，界面焦点属于条目。

`graph/lut.py` 提供实际安装的 LUT 和原生 float32 适配矩阵快照。`scopes/sampling.py` 通过这些资源计算堆栈输入／输出；重新烘焙期间继续使用已安装结果。`scopes/color.py` 在所选 Grade 的上下文中测量最终输出。不会运行解析采样图像预览。所选 Grade 的模型仅用于控制曲线和手柄数学。
