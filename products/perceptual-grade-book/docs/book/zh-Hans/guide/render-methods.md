# 渲染方法

> **保留版本：** 本使用章节及截图描述 1.23.2，仍滞后于最新模型。当前参考见[理解模型](../theory/structure.md)；这些控件并非 Next 未来的 Warp 实现。

普通 **Grade（调色）** 节点始终正向应用 Grade。在 Perceptual Grade 侧栏选择 **Baked LUT（烘焙 LUT）** 或 **Direct（直接求值）**。节点本体显示 Grade 选择器和用于显示／隐藏图表的铅笔，不显示渲染方法或方向下拉框。Resolve 中的 Perceptual Grade DCTL 直接计算解析方程。

## 根据用途选择

着色通常可先选择烘焙 LUT：材质在多次采样与光线反弹中复用预计算结果。合成通常可先选择直接求值：原生节点计算模型，避免整幅渐变上的有限三维网格误差。

普通节点的 LUT 存储影调与色彩变换，线性矩阵保持在 LUT 外。直接求值使用平滑的一维系数表计算外观与色彩操作。对于强调整或困难渐变，应比较两种方法后选择最终渲染设置。

渲染方法属于节点。同一个 Grade 可以被不同渲染方法的节点共享。工作白点属于 Grade，只在阶段 1 的侧栏中显示。

## 编辑期间

普通调色节点选择烘焙 LUT 时，在准备新表期间暂时采用直接求值；匹配的新表完成后接管输出。最终渲染等待当前表完成。直接求值节点始终保持直接求值。

## 自动 GPU 烘焙

从 1.23.0 起，非线性 LUT 烘焙会自动使用通过启动着色器检查的 Blender 图形设备，
包括普通 Grade 的正向 LUT 和正向／反向 Grade Stack。渲染方式仍是“烘焙 LUT”；
GPU 或 CPU 指的是生成这张表的方法。

侧栏显示“烘焙：GPU”及实际图形后端／设备，或“烘焙：CPU”及回退原因。
选择依据是 Blender 图形上下文，与 Cycles 的 CPU／Metal／CUDA 设置、合成器渲染设备无关。
仅含矩阵的变换不需要非线性求解，继续使用 CPU；软件图形设备、缺少上下文、着色器
检查失败和奇异反向矩阵也回退 CPU。

着色器源代码由 Blender 自身 GPU API 编译。第一次使用可能等待驱动编译，随后编辑复用
同一程序。温态计算分成有限批次；设备标记的反向顶点在发布前通过完整 CPU 变换重新
求值。GPU 使用 float32，CPU 使用 float64，反向容差不同，因此 GPU 表有独立诊断，
不保证与 CPU 顶点逐位相同。参见[验证与工作站测量](../development/testing.md#installed-gpu-baking-1230)。

GPU 计算在绘图上下文运行。如果保存或渲染要求的表尚未完成，会用 CPU 完成；
已经安装且匹配参数的 GPU 表直接复用。扩展不需要额外 GPU 包或预编译扩展二进制。

### GPU 启动错误与日志

“正在准备 GPU 烘焙”表示任务等待绘图上下文中的 GPU 启动。
1.23.2 在向量列上完成反向着色器的整个 Broyden 更新，避免日志中 Metal 编译器
不支持的 `outerProduct` 内建函数和矩阵／标量除法。
编译或计算失败会转 CPU，侧栏保留异常类型／消息，控制台为每个图形上下文
输出一次警告及完整调用栈。禁用后重新启用扩展，或重新启动 Blender，才会重试失败的上下文。

扩展没有单独的日志文件。在 macOS 上保存项目并退出 Blender，然后从 Terminal 启动：

```sh
/Applications/Blender.app/Contents/MacOS/Blender --debug-gpu \
  2>&1 | tee "$HOME/Desktop/perceptual-grade-gpu.log"
```

若安装位置不同，请调整应用路径。复现烘焙后，终端输出也会保存为桌面上的
`perceptual-grade-gpu.log`。物理 Metal 编译与性能仍需在 Mac 上验证；
软件 OpenGL 算术测试不能替代这项检查。

## 调色堆栈

**Grade Stack（调色堆栈）** 每次使用一个 LUT，编辑预览为 33³，最终质量为 65³，包含整个已启用序列及每个线性矩阵。各条目有正向／反向开关。只需一个反向 Grade 时，使用单条目的反向堆栈。

堆栈先安装 33³ LUT，快速更新节点输出和示波器；编辑稳定后复用所有预览顶点，细化至 65³。连续修改合并为后续预览请求。示波器与原生节点输出始终使用同一已安装 LUT。最终渲染及正常保存要求最新参数的 65³ 结果。首个预览完成前节点直通，示波器等待。调度与精度细节见堆栈指南。

参见[反向调色与调色堆栈](inverse-stack.md)、[求值与插值](../theory/lut.md)和[渲染方法测量](../development/testing.md#measure-render-methods)。
