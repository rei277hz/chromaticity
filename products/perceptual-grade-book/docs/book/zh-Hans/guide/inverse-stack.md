# 反向调色与调色堆栈

普通 **Grade（调色）** 节点始终正向应用共享 Grade。需要反向变换时，从节点编辑器的颜色菜单添加 **Perceptual Grade Stack**，再启用条目的反向开关。节点标题为 **Grade Stack（调色堆栈）**。两个添加菜单项均使用与 Grade 选择器相同的颜色图标。

## 排列堆栈

各条目引用共享 Grade，已启用的条目按**从上到下**的顺序执行。例如：

| 条目 | Grade | 应用方式 |
|---|---|---|
| 1 | Grade.001 | 正向 |
| 2 | Grade.002 | 反向 |
| 3 | Grade.003 | 正向 |

Alpha 原样通过。空条目和旁路条目会跳过；没有已启用 Grade 的堆栈为恒等变换。

列表属于当前节点。复制堆栈会独立复制列表，Grade 引用仍然共享。启用状态、方向和位置属于条目；调色参数与工作白点属于共享 Grade。

堆栈初始宽度与普通调色节点相同。每个条目有一行选择器和一行紧凑控制：

| 控件 | 行为 |
|---|---|
| 眼睛 | 启用或旁路条目，保留其设置和位置。 |
| \(f^{-1}\) | 切换正向／反向；图案不变，高亮表示**反向**。 |
| 铅笔 | 打开此条目的 Grade 图表并开始编辑；高亮表示当前编辑目标，再次点击关闭。 |
| 上／下 | 调整执行顺序。 |
| × | 移除条目，保留共享 Grade 数据。 |

“添加调色”创建一个已启用、正向应用的空条目。选择器自带的解除关联按钮仅清空 Grade 引用。只选择堆栈不会自动打开图表。

## 编辑 Grade，观察整个堆栈

点击已启用条目的铅笔，图表与侧栏便编辑其**共享 Grade**。所有引用该 Grade 的普通节点和其他堆栈都会更新。需要独立调整时，先在普通调色节点中创建 Grade 的独立副本，再为条目选择该副本。

图表标明当前 Grade 和方向。点击另一支铅笔切换编辑目标。重排时跟随所选条目，即使同一个 Grade 被引用多次也不会混淆。移除、解除关联或旁路当前条目会结束编辑。旁路、空白或只读条目的铅笔变灰。

反向条目的手柄仍编辑 Grade 存储的**正向参数**；烘焙器再求这些参数定义的反向变换。工作白点只出现在所选 Grade 的**阶段 1 侧栏**，修改后影响该 Grade 的所有用户。

## 阅读图表

| 阶段 | 手柄与曲线 | 图像示波器 |
|---|---|---|
| 线性 | 所选 Grade 的矩阵控制 | 完整堆栈输出的矢量示波器 |
| 影调 | 所选 Grade 的影调曲线；控制点位于曲线上 | **堆栈输入／堆栈输出**波形和直方图 |
| 色彩 | 所选 Grade 的贡献曲线和控制 | 以所选 Grade 的感知条件测量完整堆栈输出 |

输入与输出的影调示波器采用相同的 Grade 白点和参考设置。Grade 曲线表示该 Grade 的影调操作；整个堆栈通常无法用一条一维影调曲线表示。堆栈编辑模式的波形上不再放置局部 Grade 的影调手柄。

阶段 3 的图像直方图、色调范围选择和中性统计均测量**堆栈输出**。驱动定义及可编辑曲线属于所选 Grade。合并 LUT 不提供条目之间的中间图像。

Rec.709 矢量示波器保留原有信号约定。在堆栈模式中，线性矢量示波器用于观察；请使用 xy 等线性手柄调整 Grade。完整堆栈的响应不能作为普通节点矢量示波器拖动所假定的独立矩阵响应。

“堆栈输出”指当前节点的输出，位于后续节点及 Blender 视图变换之前。

## 烘焙与示波器更新

每个堆栈每次使用**一个 LUT：交互预览为 33³，编辑稳定后为 65³**，包含所有已启用条目的全部三个阶段，包括每个线性矩阵。烘焙器在最终网格顶点直接计算整个序列的正向方程和尽力反解，不串联已有的 Grade LUT。

修改引用的 Grade、启用状态、方向或顺序，会自动安排预览和最终细化。仅重命名不会改变变换或 LUT。线性阶段也位于堆栈 LUT 内，因此线性编辑同样触发烘焙。烘焙期间使用 Bradford 连接各 Grade 白点；LUT 的边界仍固定为线性 原生 ACEScg／ACES 白点，场景坐标适配矩阵位于 LUT 外。

**示波器只使用当前已安装的 LUT。** 33³ 预览同时更新原生节点输出和示波器。手柄、曲线立即更新；状态文字标明正在显示 33³ 预览并等待 65³ 细化。没有额外的解析采样图像预览。

首次预览在 40 ms 后可开始。连续拖动时，正在计算的 33³ 参数快照会完成并显示，期间的新修改合并为一个最新请求；因此预览可能短暂落后于手柄，但持续移动不会一直取消预览。距上次编辑至少 300 ms，且匹配的预览已经完成后，才开始 65³ 细化。这些时间是调度阈值，不是烘焙耗时保证。新预览准备好之前保留上一个已安装结果。

33 点坐标轴取自 65 点坐标轴的每隔一个顶点。全部 **35,937** 个预览顶点原样复用，细化仅计算其余 **238,688** 个顶点。对于同一参数快照，总解析计算量仍为 274,625 个顶点，不从粗网格插值生成最终顶点。预览每轴有 32 个正侧单元，保持相同的原生 ACEScg／ACES 白点坐标、0…1024 边界及普通 log1p κ = 0.01 曲线。网格之外的输入取最近边缘单元而不做外推；边界规则见[直接求值与采样求值](../theory/lut.md)。

首次预览完成前节点直通，示波器等待。预览和最终 LUT 安装时都会刷新示波器；二者使用不同的缓存标识与紧凑图集尺寸。过期的最终结果不能发布。即使已安装预览，最终渲染准备及正常保存仍等待**最新参数的 65³** 结果。普通 Grade 节点的渲染方法行为不变。

反向烘焙会自动优先使用可用的 Blender 计算着色器，Python／NumPy 为 CPU 回退路径。
每个 GPU 顶点计算整个序列，不查询中间 Grade 表。设备标记的反向顶点在安装前通过
完整 float64 CPU 序列重新求值。侧栏显示所选后端和回退原因。已发布的匹配 GPU 预览
在细化改用 CPU 时保留公共顶点。前台保存／渲染回调没有保证的绘图上下文，因此待完成
的表使用 CPU 完成；已完成且匹配参数的 GPU 表不必重新烘焙。

黑点裁剪、奇异矩阵、负值分支和强色彩折叠可能丢失信息或产生多个原像，因此反向为
尽力求解。奇异矩阵使用 CPU 伪逆；CPU 诊断记录复现误差和奇异矩阵数量，GPU 诊断记录
float32 策略、RGB 搜索及修复顶点。GPU 诊断不代表未标记顶点满足更严格的 CPU 残差容差。
网格之间的插值仍有独立误差。参见[自动 GPU 烘焙](render-methods.md#自动-gpu-烘焙)。

## 保存与共享

正常保存会打包最终 LUT 和原生计算图。关闭扩展后仍可渲染已保存外观；编辑、自动重新烘焙和动画更新需要扩展。着色与合成编辑器使用相同的共享 Grade 和堆栈行为。

参见[渲染方法](render-methods.md)、[工作白点](working-white.md)、[求值与插值](../theory/lut.md)及[正向／反向数学规范](../development/forward-inverse-math.md)。
